Servidores MCP e agentes de IA

O que é um servidor MCP e como ele conecta o ChatGPT e o Claude aos sistemas da sua empresa

Um servidor MCP é um programa que dá a um assistente de IA, como o ChatGPT ou o Claude, acesso controlado aos sistemas da sua empresa. Por meio dele, a IA consegue consultar um pedido, um cliente ou o estoque, e até registrar uma informação, sem que alguém precise copiar e colar dados para dentro do chat.

MCP é a sigla de Model Context Protocol, um padrão aberto. Na prática, a empresa constrói (ou contrata) um servidor MCP uma vez, define o que a IA pode ler e o que pode alterar, e esse mesmo servidor funciona nos principais assistentes de IA do mercado.

O MCP em uma explicação curta

Pense numa tomada padrão. Antes dela, cada aparelho precisava de um adaptador diferente. O MCP faz o mesmo papel entre a inteligência artificial e os sistemas: em vez de criar uma integração específica para cada assistente de IA, você cria um servidor que segue o padrão, e qualquer assistente compatível consegue usá-lo.

O protocolo foi criado pela Anthropic, empresa do Claude, e lançado como padrão aberto. Em dezembro de 2025, a Anthropic doou o MCP para a Agentic AI Foundation, uma fundação ligada à Linux Foundation criada junto com a OpenAI e a Block. No mesmo anúncio, a empresa informou mais de 10 mil servidores MCP públicos ativos e citou ChatGPT, Gemini, Microsoft Copilot, Cursor e Visual Studio Code entre os produtos que adotaram o protocolo.

Para quem decide, isso significa que o MCP não é aposta em um fornecedor: o servidor construído para o Claude também pode ser usado no ChatGPT.

Como um servidor MCP funciona na prática

Há três peças envolvidas:

  • O assistente de IA (ChatGPT, Claude, Copilot etc.), que conversa com a pessoa e decide quando precisa de uma informação de fora.
  • O servidor MCP, que fica entre a IA e os seus sistemas. Ele diz à IA o que está disponível e executa os pedidos dentro das regras definidas.
  • Os seus sistemas: o ERP, o CRM, o banco de dados, a planilha que virou sistema, a API de um parceiro.

Veja um exemplo de pergunta feita por alguém do comercial dentro do Claude ou do ChatGPT:

  1. A pessoa pergunta: “Quais pedidos do cliente Silva estão atrasados?”.
  2. A IA percebe que não sabe a resposta e vê que o servidor MCP da empresa tem uma ferramenta chamada, por exemplo, “buscar pedidos”.
  3. A IA chama essa ferramenta com os parâmetros certos (cliente = Silva, situação = atrasado).
  4. O servidor MCP confere se aquela pessoa tem permissão, consulta o sistema de pedidos e devolve só os dados necessários.
  5. A IA lê o resultado e responde em linguagem natural, já sugerindo o próximo passo.

Ninguém exportou relatório nem abriu três telas. E a regra de quem pode ver o quê continua no seu sistema, não na boa vontade da IA.

O que um servidor MCP oferece à IA

O protocolo organiza o que o servidor expõe em três tipos principais:

  • Ferramentas: ações que a IA pode executar, como buscar um cliente, criar um orçamento ou atualizar o status de um chamado. É o tipo mais usado.
  • Recursos: conteúdos que a IA pode ler como contexto, como uma tabela de preços, um manual interno ou um contrato.
  • Prompts: roteiros prontos que a empresa deixa disponíveis, como “resumir a semana do cliente X”.

Cada ferramenta tem nome, descrição e os campos que aceita. Uma boa parte do trabalho está aqui: escrever essas descrições de um jeito que a IA entenda quando usar cada uma, e quando não usar.

MCP, API e integração: qual a diferença

É a dúvida mais comum. O MCP não substitui a API do seu sistema. Na maioria dos casos, o servidor MCP usa a API (ou o banco de dados) que já existe e acrescenta uma camada pensada para a IA.

Comparação entre API tradicional, integração entre sistemas e servidor MCP
API tradicional Integração entre sistemas Servidor MCP
Quem usa Programadores e outros sistemas Sistemas, de forma automática Assistentes e agentes de IA
Quando roda Quando alguém programa a chamada Em eventos ou horários definidos Quando a IA decide, a partir de um pedido em linguagem natural
Para que serve Expor dados e ações de um sistema Manter dados sincronizados, sem retrabalho Deixar a IA consultar e agir com contexto e permissão
Exemplo Endpoint que lista pedidos Pedido do e-commerce entra sozinho no ERP “Quais pedidos do cliente Silva estão atrasados?”

As três coisas convivem. Se o problema é dado repetido em dois sistemas, o caminho é uma integração entre plataformas. Se o problema é a equipe perder tempo procurando informação ou fazendo tarefas que dependem de interpretação, o MCP entra bem.

O que dá para fazer numa pequena ou média empresa

Os melhores usos costumam ser tarefas frequentes, que exigem consultar mais de um lugar e que hoje dependem de alguém “que sabe onde está”. Alguns exemplos:

  • Comercial: perguntar quais leads estão sem retorno há mais de uma semana, registrar o resumo de uma reunião no CRM, preparar uma proposta com base no histórico do cliente.
  • Atendimento: consultar o status de um pedido ou chamado durante a conversa, sem trocar de tela.
  • Financeiro: listar contas a receber vencidas e montar a cobrança, com a pessoa revisando antes de enviar.
  • Operação e estoque: saber o que está abaixo do mínimo e o que já tem pedido de compra em aberto.

Um ponto que vale para todos os casos: a IA ganha com o servidor MCP na mesma medida em que os dados do sistema são confiáveis. Se o cadastro de clientes está bagunçado, a IA vai responder com a mesma bagunça, só que mais rápido.

Servidor pronto ou servidor próprio?

Muitos softwares conhecidos já oferecem o próprio servidor MCP, ou “conector”, como o ChatGPT e o Claude costumam chamar. Se a ferramenta que você usa já tem um, comece por ele: é rápido de ativar e a manutenção fica com o fornecedor.

O servidor próprio faz sentido quando:

  • o dado está num sistema sob medida, num sistema legado ou num banco de dados interno, que não tem conector pronto;
  • a empresa precisa juntar informações de mais de um sistema numa mesma resposta;
  • o conector pronto expõe coisa demais (ou de menos), e você precisa controlar exatamente o que a IA vê e faz;
  • as ações seguem regras do seu negócio, como “desconto acima de 10% precisa de aprovação”;
  • você quer oferecer o seu próprio produto como conector para os clientes usarem nos assistentes de IA deles.

Um servidor próprio não é um projeto que termina na entrega. O protocolo evolui (a versão atual da especificação, de julho de 2026, mudou a forma como cliente e servidor se comunicam), os assistentes mudam de comportamento e os seus sistemas também mudam. Por isso, ele funciona melhor como parte de uma relação contínua de manutenção do que como entrega pontual.

Segurança: o que precisa estar resolvido antes

Dar acesso aos sistemas para uma IA exige o mesmo cuidado de dar acesso a um funcionário novo, com um detalhe a mais: a IA pode ser enganada por textos que lê. OpenAI e Anthropic alertam, nas próprias páginas de ajuda, para conectar só servidores MCP confiáveis, porque um servidor malicioso pode trazer instruções escondidas que levam a IA a alterar ou apagar dados.

Use esta lista antes de colocar um servidor MCP em uso:

  • Leitura separada de escrita. Comece só com consultas. Libere ações que alteram dados uma a uma, quando fizer sentido.
  • Permissão de cada pessoa, não do servidor. A IA deve enxergar o que o usuário que está conversando com ela pode enxergar. Login por usuário (OAuth) evita que todos usem a mesma chave com acesso total.
  • Confirmação humana nas ações sensíveis. Excluir, enviar mensagem para cliente, mexer em valores: alguém confirma antes. O ChatGPT, por exemplo, já pede confirmação para ferramentas que não estão marcadas como somente leitura.
  • Regra no código, não no texto. “Não mostre o salário dos outros” não pode ser só uma instrução para a IA. Precisa ser uma regra no servidor que simplesmente não devolve aquele dado.
  • Registro de tudo. Cada chamada feita pela IA fica registrada com quem pediu, o quê e quando.
  • Dados mínimos. O servidor devolve só o necessário para a resposta. Isso reduz risco e ajuda no cumprimento da LGPD.
  • Cuidado com servidores de terceiros. Antes de ativar um conector que você não conhece, verifique quem mantém, quais permissões ele pede e desative as ferramentas que não vai usar.

Esses pontos seguem o guia de segurança de MCP da OWASP, referência internacional em segurança de aplicações.

Passo a passo para o primeiro servidor MCP

Para uma pequena ou média empresa, o caminho mais seguro é começar pequeno e crescer pelo uso real:

  1. Escolha uma tarefa só. Uma pergunta que a equipe faz toda semana e que hoje toma tempo. Exemplo: “qual a situação deste cliente?”.
  2. Mapeie de onde vem cada informação. Quais sistemas, quais tabelas ou APIs, quem é o dono de cada dado.
  3. Defina as ferramentas. Poucas, com nomes e descrições claras. Três ferramentas bem feitas valem mais do que trinta genéricas.
  4. Decida as permissões. Quem pode usar, o que cada perfil vê, o que é só leitura e o que exige confirmação.
  5. Teste nos assistentes que a equipe usa. O mesmo servidor pode se comportar de forma diferente no Claude e no ChatGPT. Teste com perguntas reais, inclusive as mal escritas.
  6. Coloque em produção com registro e acompanhe. Nas primeiras semanas, leia os registros: o que a IA chamou, o que errou, o que a equipe pediu e não tinha.
  7. Só então amplie. Nova ferramenta, nova área, primeiras ações de escrita.

Do lado técnico, existem kits oficiais de desenvolvimento em várias linguagens (TypeScript, Python, Go e C#, entre outras), e o servidor pode rodar na nuvem para ser usado pelos assistentes na web. No Claude, conectores personalizados estão disponíveis em todos os planos, inclusive o gratuito (limitado a um conector). No ChatGPT, servidores MCP próprios também podem ser adicionados, sujeitos às permissões do workspace.

Perguntas frequentes

Preciso trocar meu sistema para usar MCP?

Não. O servidor MCP se conecta ao que já existe, normalmente pela API ou pelo banco de dados do sistema. Se o sistema não tem nenhuma forma de acesso, esse é o primeiro ponto a resolver.

O MCP substitui a API do sistema?

Não. A API continua sendo a porta de entrada do sistema. O servidor MCP é uma camada por cima, que traduz essa porta para algo que a IA entende e aplica as regras de acesso.

É seguro deixar a IA alterar dados da empresa?

Pode ser, desde que as permissões sejam por usuário, as ações sensíveis exijam confirmação e tudo fique registrado. O recomendado é começar só com leitura e liberar escrita aos poucos.

O mesmo servidor funciona no ChatGPT e no Claude?

Sim, esse é o objetivo do padrão. Ainda assim, vale testar nos dois, porque cada assistente decide de um jeito quando chamar cada ferramenta.

Minha empresa precisa ter programador para isso?

Para ativar um conector pronto, não. Para um servidor próprio, sim: é desenvolvimento de software, com atenção especial a segurança e manutenção. Por isso muitas empresas preferem contratar e manter com um parceiro de tecnologia.

Por onde começar na sua empresa

Se a sua equipe já usa ChatGPT ou Claude e passa o dia copiando informação dos sistemas para dentro do chat, um servidor MCP provavelmente vai economizar tempo. A pergunta certa não é “qual tecnologia usar”, e sim “qual tarefa repetitiva queremos tirar da frente primeiro”.
